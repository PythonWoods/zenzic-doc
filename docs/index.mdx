**Zenzic guarantees build-time safety and operational peace of mind — detecting broken links,
leaked credentials, and orphan pages before they reach production. No configuration required to
start. No build engine invoked. No surprises on Friday.**

## Shield — Your Last Line of Defense Against the Dark Crisis

A leaked API key in your documentation is not a content issue. It is a security incident.

<SentinelOutput variant="breach" showFrame />

Zenzic's **Shield** scans every line of every file — including YAML frontmatter and code
blocks — before any other check runs. If a credential is detected:

- The pipeline **halts unconditionally** — exit code 2 cannot be suppressed by any flag
- The credential is **masked** in the report (never printed in full)
- You fix it **before it reaches git history** — no BFG Repo Cleaner, no emergency rotations
  at midnight, no incident post-mortem

This is not a lint check. It is a **non-negotiable security gate**.

## Enterprise Ready — Native GitHub Integration

```yaml title=".github/workflows/zenzic.yml"
- uses: PythonWoods/zenzic-action@v1
  with:
    format: sarif
    upload-sarif: "true"
```

Findings appear as **inline Pull Request annotations** and in the **Security tab** —
no log parsing, no custom scripts, no post-processing. The official
[`PythonWoods/zenzic-action`](https://github.com/PythonWoods/zenzic-action) handles
installation, execution, and SARIF 2.1.0 upload in a single workflow step.

Cross-platform verified: Ubuntu · Windows · macOS · Python 3.11–3.13.
