# Examples

Every example in the Zenzic repository is a **self-contained Z-code violation fixture**.
Clone it. Run `uvx zenzic check all`. Each example isolates one Z-code violation class —
the code shown is the minimum required to reproduce the reported exit code.

All examples are located in [`examples/`](https://github.com/PythonWoods/zenzic/tree/main/examples) in the Zenzic repository.

---

## Quick-Run Pattern {#quick-run}

Every example follows the same convention:

```bash
# From the repo root — no install required
cd examples/<z-code-dir>
uvx zenzic check all
```

Or launch the interactive gallery:

```bash
uvx zenzic lab            # gallery menu
uvx zenzic lab z101       # run the Z101 scenario
uvx zenzic lab all        # run all 5 scenarios
```

## Z-Code Gallery {#gallery}

### z101-broken-links — Link Integrity {#example-z101}

**Directory:** `examples/z101-broken-links/`
**Engine:** `standalone`
**Z-Code:** Z101 `LINK_BROKEN`
<ZenzicOutput status="error" exitCode={1} compact />

Demonstrates Zenzic detecting Markdown links that point to files that do not exist.
The fixture contains `docs/index.md` with two broken links — one to a missing page and
one to a non-existent anchor. Both trigger Z101 findings.

**Start here if:** you want to understand how Zenzic validates internal link references.

---

### z201-credentials — Credential Scanner {#example-z201}

**Directory:** `examples/z201-credentials/`
**Engine:** `standalone`
**Z-Code:** Z201 `CREDENTIAL_SECRET`
<ZenzicOutput status="breach" exitCode={2} compact />

Contains a synthetic AWS access key embedded in `docs/setup.md`. Zenzic fires the
**security_breach** severity finding — the non-suppressible alert for a leaked credential.
Exit code 2 is expected and correct.

:::danger[This example exits with code 2 by design]
`z201-credentials` contains an intentionally-placed synthetic credential for credential
scanner testing. Do **not** treat exit code 2 from this example as a real security incident.
:::

**Start here if:** you want to see how the credential scanner detects and reports secrets.

---

### z405-unused-assets — Asset Integrity {#example-z405}

**Directory:** `examples/z405-unused-assets/`
**Engine:** `standalone`
**Z-Code:** Z405 `UNREFERENCED_ASSET`
<ZenzicOutput status="error" exitCode={1} compact />

Contains `assets/banner.png` — an image file that exists on disk but is never linked
from any Markdown document. Zenzic detects the orphan asset and reports Z405.

**Start here if:** you want to validate that every asset in your project is actually used.

---

### z601-brand-obsolescence — Brand Obsolescence {#example-z601}

**Directory:** `examples/z601-brand-obsolescence/`
**Engine:** `standalone`
**Z-Code:** Z601 `BRAND_OBSOLESCENCE`
<ZenzicOutput status="error" exitCode={1} compact />

The `.zenzic.toml` declares `OldPlatform` as an obsolete brand name. The fixture's
`docs/index.md` mentions `OldPlatform` — triggering Z601 findings on every occurrence.

**Start here if:** you maintain a governance list of deprecated product names or brands
that must be eliminated from documentation.

---

### z602-i18n-parity — i18n Parity {#example-z602}

**Directory:** `examples/z602-i18n-parity/`
**Engine:** `standalone`
**Z-Code:** Z602 `I18N_PARITY`
<ZenzicOutput status="error" exitCode={1} compact />

`docs/en/` contains two pages: `index.md` and `guide.md`. The Italian locale
`docs/it/` has only `index.md` — `guide.md` is missing. Zenzic detects the parity
gap and reports Z602.

**Start here if:** you maintain multilingual documentation and need to enforce that every
page translated in one locale also exists in all other configured locales.
