# Your First Audit

**What you'll achieve:** go from zero to a passing Sentinel report in under three minutes —
and along the way, watch Zenzic catch a leaked credential, flag an orphan page, and hand you
a 100/100 score. No configuration file required to start.

:::tip[Prerequisites]

You need [uv](https://docs.astral.sh/uv/) on your `PATH`. Everything else is handled automatically.
:::

:::info[Why start with the Lab?]

The fastest path to understanding Zenzic is not reading — it is **watching it work**.
`zenzic lab` is an interactive showcase of every scanner running against pre-built fixtures.
You will see a real security breach, a real shield, and a real clean report — in 60 seconds.
:::

---

## Step 1 — Run Zenzic without installing it {#step-1-uvx}

Point Zenzic at any Markdown folder. No virtual environment, no `pip install`:

```bash
uvx zenzic check all --docs path/to/your/docs
```

`uvx` fetches Zenzic in an isolated environment and discards it when the command finishes.
This is the recommended workflow for CI and for trying Zenzic on an unfamiliar repo.

## Step 2 — The Siege & The Shield {#step-2-siege}

Before configuring anything, watch Zenzic protect a deliberately broken repo:

**The Siege** — run act 2 (leaked credential demo):

```bash
uvx zenzic lab 2
```

Zenzic scans the bundled `security_lab` fixture and fires **exit code 2** with the
Security Breach banner — the non-suppressible alert for a leaked credential:

<SentinelOutput variant="breach" showFrame
  location="docs/how-to/configure.md:4"
  masked="AKIA************MPLE"
  credentialType="aws-access-key"
/>

The masked credential, the non-zero exit: this is how Zenzic teaches.

**The Shield (Sentinel Seal)** — now run act 0:

```bash
uvx zenzic lab 0
```

You'll see the Sentinel Seal: every check green, exit 0. The contrast is the lesson —
the same engine that caught the secret just confirmed that clean docs are genuinely clean.

:::tip[Interactive Demo — No installation required]
**Want to see the AI siege live?**

```bash
uvx zenzic lab
```

Launches the interactive menu of all 11 scenarios: credential leaks, broken links, orphan pages,
path traversal, and the Sentinel Seal. Zero install. Zero config. Pure experience.

→ Pick any act from the menu, or run a specific one: `uvx zenzic lab 2` (The Siege), `uvx zenzic lab 0` (The Seal).
:::

## Step 3 — Initialize your Safe Harbor {#step-3-init}

When you're ready to commit Zenzic to your project, generate a `zenzic.toml` in one command:

```bash
cd your-project/
zenzic init
```

Zenzic inspects the directory and pre-configures the engine for you:

```text
Created zenzic.toml
  Engine pre-set to docusaurus (detected from docusaurus.config.ts).

Edit the file to enable rules, adjust directories, or set a quality threshold.
Run zenzic check all to validate your documentation.
```

The generated file is annotated — every option is commented out with a short explanation.
Open it, uncomment what you need, leave the rest.

:::note[Using pyproject.toml?]

```bash
zenzic init --pyproject
```

This appends a `[tool.zenzic]` section to your existing `pyproject.toml` instead of
creating a separate file.
:::

## Step 4 — Run your first real audit {#step-4-audit}

```bash
zenzic check all
```

The Sentinel scans every Markdown file, validates internal links against the Virtual Site Map,
checks anchors, scans for credentials, and runs your custom rules — then prints a structured
report and exits with a machine-readable code:

| Code | Meaning |
| :---: | :--- |
| **0** | Clean — no issues found |
| **1** | Findings — documentation quality issues detected |
| **2** | Shield — leaked credential detected (never suppressed) |
| **3** | Blood Sentinel — path traversal attempt detected (never suppressed) |

This is not a green CI tick. It is a **mathematical proof** that every link resolves,
every page is reachable, and no credential is exposed. `100/100` is the only number that counts.

> **Ready to get there?** Run `uvx zenzic score` on your own repo — right now, without installing anything.

## What's next? {#next}

- **Measure your score** — run `uvx zenzic score` to get a precise 0–100 baseline for your repo
- **Add a CI gate** — see [CI/CD Integration](../how-to/configure-ci-cd) to ship with confidence
- **SARIF export** — `zenzic check all --format sarif` for GitHub Code Scanning inline annotations
- **Strict mode** — add `--strict` to also validate external URLs
- **Custom rules** — add `[[custom_rules]]` entries to `zenzic.toml` to enforce your own patterns
- **Finding codes** — see the [Finding Codes reference](../reference/finding-codes) for the full
  `Zxxx` diagnostic catalogue
