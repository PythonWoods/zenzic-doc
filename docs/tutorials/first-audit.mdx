# Your First Audit

**What you'll do:** go from a folder of Markdown files to a passing Sentinel report in under
three minutes — no configuration file required to start.

:::tip Prerequisites
You need [uv](https://docs.astral.sh/uv/) on your `PATH`. Everything else is handled automatically.
:::

---

## Step 1 — Run Zenzic without installing it {#step-1-uvx}

Point Zenzic at any Markdown folder. No virtual environment, no `pip install`:

```bash
uvx zenzic check all --docs path/to/your/docs
```

`uvx` fetches Zenzic in an isolated environment and discards it when the command finishes.
This is the recommended workflow for CI and for trying Zenzic on an unfamiliar repo.

---

## Step 2 — Explore the Sentinel Arsenal {#step-2-lab}

Before configuring anything, watch what the Sentinel can detect:

```bash
uvx zenzic lab
```

The interactive Lab presents a menu of scenarios — broken links, leaked credentials,
path-traversal probes, orphaned pages, and more. Pick any act and see Zenzic diagnose
it live with the same output format it uses in production.

```text
┌─────────────────────────────────────────────────┐
│  Zenzic Lab — choose an act or press Enter for  │
│  the full showcase                               │
│                                                  │
│   1 · Z101 Broken Link                          │
│   2 · Z201 Shield — leaked credential           │
│   3 · Z202 Blood Sentinel — path traversal      │
│   …                                             │
└─────────────────────────────────────────────────┘
```

Run a specific act directly:

```bash
uvx zenzic lab 3   # path-traversal detection live demo
```

## Step 3 — Initialize your Safe Harbor {#step-3-init}

When you're ready to commit Zenzic to your project, generate a `zenzic.toml` in one command:

```bash
cd your-project/
zenzic init
```

Zenzic inspects the directory and pre-configures the engine for you:

```text
Created zenzic.toml
  Engine pre-set to docusaurus (detected from docusaurus.config.ts).

Edit the file to enable rules, adjust directories, or set a quality threshold.
Run zenzic check all to validate your documentation.
```

The generated file is annotated — every option is commented out with a short explanation.
Open it, uncomment what you need, leave the rest.

:::note Using pyproject.toml?
```bash
zenzic init --pyproject
```
This appends a `[tool.zenzic]` section to your existing `pyproject.toml` instead of
creating a separate file.
:::

## Step 4 — Run your first real audit {#step-4-audit}

```bash
zenzic check all
```

The Sentinel scans every Markdown file, validates internal links against the Virtual Site Map,
checks anchors, scans for credentials, and runs your custom rules — then prints a structured
report and exits with a machine-readable code:

| Code | Meaning |
| :---: | :--- |
| **0** | Clean — no issues found |
| **1** | Findings — documentation quality issues detected |
| **2** | Shield — leaked credential detected (never suppressed) |
| **3** | Blood Sentinel — path traversal attempt detected (never suppressed) |

A clean run looks like this:

```text
 ✔  No broken links found
 ✔  Shield: no credentials detected
 ✔  Blood Sentinel: no path-traversal attempts
 ✔  No orphaned pages
────────────────────────────────────────
  Files scanned: 42    Elapsed: 0.31 s
```
