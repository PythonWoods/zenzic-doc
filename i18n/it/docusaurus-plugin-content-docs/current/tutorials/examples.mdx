# Esempi

Ogni esempio nel repository Zenzic è un **fixture di violazione Z-code autonomo**.
Clonalo. Esegui `uvx zenzic check all`. Ogni esempio isola una classe di violazione Z-code —
il codice mostrato è il minimo necessario per riprodurre l'exit code riportato.

Tutti gli esempi si trovano in [`examples/`](https://github.com/PythonWoods/zenzic/tree/main/examples) nel repository Zenzic.

---

## Pattern di Esecuzione Rapida {#quick-run}

Ogni esempio segue la stessa convenzione:

```bash
# Dalla root del repo — nessuna installazione richiesta
cd examples/<z-code-dir>
uvx zenzic check all
```

Oppure lancia la galleria interattiva:

```bash
uvx zenzic lab            # menu della galleria
uvx zenzic lab z101       # esegui lo scenario Z101
uvx zenzic lab all        # esegui tutti e 20 gli scenari
```

## Galleria Z-Code {#gallery}

### z101-broken-links — Integrità dei Link {#example-z101}

**Directory:** `examples/z1xx-links/z101-broken-links/`
**Engine:** `standalone`
**Z-Code:** Z101 `LINK_BROKEN`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

Dimostra come Zenzic rileva link Markdown che puntano a file non esistenti.
Il fixture contiene `docs/index.md` con due link rotti — uno verso un file mancante
(`missing.md`) e uno verso un file in una sottodirectory inesistente (`guide/setup.md`).
Entrambi generano finding Z101.

**Parti da qui se:** vuoi capire come Zenzic valida i riferimenti di link interni.

### z201-credentials — Credential Scanner {#example-z201}

**Directory:** `examples/z2xx-security/z201-credentials/`
**Engine:** `standalone`
**Z-Code:** Z201 `CREDENTIAL_SECRET`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ SECURITY BREACH — exit 2</span></ZenzicTerminal>

Contiene una chiave di accesso AWS sintetica incorporata in `docs/setup.md`. Zenzic attiva
il finding di severity **security_breach** — l'allerta non sopprimibile per una credenziale esposta.
L'exit code 2 è atteso e corretto.

:::danger[Questo esempio esce con codice 2 per design]
`z201-credentials` contiene una credenziale sintetica inserita intenzionalmente per il testing
del credential scanner. **Non** trattare l'exit code 2 di questo esempio come un vero
incidente di sicurezza.
:::

**Parti da qui se:** vuoi vedere come il credential scanner rileva e segnala i segreti.

### z103-orphan-link — Link Orfano {#example-z103}

**Engine:** `zensical`
**Z-Code:** Z103 `ORPHAN_LINK`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

`docs/guide.md` esiste su disco ma non è elencato nella nav di `zensical.toml`. `index.md`
rimanda ad essa, quindi è raggiungibile via URL diretto ma invisibile dalla navigazione del sito.

### z105-absolute-path — Percorso Assoluto {#example-z105}

**Directory:** `examples/z1xx-links/z105-absolute-path/`
**Engine:** `standalone`
**Z-Code:** Z105 `ABSOLUTE_PATH`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

`docs/index.md` contiene `[Guide](/guide)` — un percorso assoluto che inizia con `/`.
I percorsi assoluti rompono la portabilità quando il sito è ospitato in una sottodirectory.

**Parti da qui se:** la tua documentazione deve essere portabile rispetto al percorso host (CDN, GitHub Pages).

### z202-path-traversal — Path Traversal {#example-z202}

**Directory:** `examples/z2xx-security/z202-path-traversal/`
**Engine:** `standalone`
**Z-Code:** Z202 `PATH_TRAVERSAL`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

`docs/index.md` contiene `[Config](../../private/secret.txt)` — un link che esce dalla

:::

**Parti da qui se:** hai bisogno di capire come Zenzic applica il confine della docs-root.

### z204-forbidden-term — Violazione di Policy {#example-z204}

**Directory:** `examples/z2xx-security/z204-forbidden-term/`
**Engine:** `standalone`
**Z-Code:** Z204 `FORBIDDEN_TERM`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ SECURITY BREACH — exit 2</span></ZenzicTerminal>

`.zenzic.local.toml` dichiara `ProjectX` come termine proibito. `docs/index.md` lo menziona —
attivando il banner **POLICY VIOLATION DETECTED** (distinto dal banner di Z201 per credenziali).
Z204 è non sopprimibile. Exit code 2.

:::danger[Questo esempio esce con codice 2 per design]
`z204-forbidden-term` contiene contenuto con termine proibito intenzionale per il testing
dello scanner di governance. Il `.zenzic.local.toml` è committato solo per dimostrazione
— in produzione è in `.gitignore`.
:::

**Parti da qui se:** devi garantire che nomi in codice interni o termini riservati non appaiano mai nella docs.

`docs/index.md` usa `[Clicca qui][missing-ref]` ma nessuna definizione `[missing-ref]: url`

**Z-Code:** Z302 `DEAD_DEF`

### z303-duplicate-def — Definizione Duplicata {#example-z303}

**Directory:** `examples/z3xx-references/z303-duplicate-def/`
**Engine:** `standalone`
**Z-Code:** Z303 `DUPLICATE_DEF`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

`docs/index.md` contiene un difetto intenzionale di definizione duplicata per l'ID di
riferimento `api`. Quando lo stesso ID viene dichiarato piu di una volta, i renderer Markdown
scelgono silenziosamente un URL, creando link drift invisibile.

**Z-Code:** Z503 `SNIPPET_ERROR`
<ZenzicTerminal title="zenzic check all"><span className="text-rose-500 font-medium">✘ 1 error — exit 1</span></ZenzicTerminal>

`docs/index.md` contiene un blocco `python` con un `SyntaxError` (`def compute_total(items =`).

`docs/index.md` contiene un blocco codice delimitato senza specificatore di linguaggio (bare ` ``` `).
