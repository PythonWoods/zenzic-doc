# Esempi

Ogni esempio nel repository Zenzic è un **fixture di violazione Z-code autonomo**.
Clonalo. Esegui `uvx zenzic check all`. Ogni esempio isola una classe di violazione Z-code —
il codice mostrato è il minimo necessario per riprodurre l'exit code riportato.

Tutti gli esempi si trovano in [`examples/`](https://github.com/PythonWoods/zenzic/tree/main/examples) nel repository Zenzic.

---

## Pattern di Esecuzione Rapida {#quick-run}

Ogni esempio segue la stessa convenzione:

```bash
# Dalla root del repo — nessuna installazione richiesta
cd examples/<z-code-dir>
uvx zenzic check all
```

Oppure lancia la galleria interattiva:

```bash
uvx zenzic lab            # menu della galleria
uvx zenzic lab z101       # esegui lo scenario Z101
uvx zenzic lab all        # esegui tutti e 5 gli scenari
```

## Galleria Z-Code {#gallery}

### z101-broken-links — Integrità dei Link {#example-z101}

**Directory:** `examples/z101-broken-links/`
**Engine:** `standalone`
**Z-Code:** Z101 `LINK_BROKEN`
<ZenzicOutput status="error" exitCode={1} compact />

Dimostra come Zenzic rileva link Markdown che puntano a file non esistenti.
Il fixture contiene `docs/index.md` con due link rotti — uno verso una pagina mancante e
uno verso un'ancora inesistente. Entrambi generano finding Z101.

**Parti da qui se:** vuoi capire come Zenzic valida i riferimenti di link interni.

---

### z201-credentials — Credential Scanner {#example-z201}

**Directory:** `examples/z201-credentials/`
**Engine:** `standalone`
**Z-Code:** Z201 `CREDENTIAL_SECRET`
<ZenzicOutput status="breach" exitCode={2} compact />

Contiene una chiave di accesso AWS sintetica incorporata in `docs/setup.md`. Zenzic attiva
il finding di severity **security_breach** — l'allerta non sopprimibile per una credenziale esposta.
L'exit code 2 è atteso e corretto.

:::danger[Questo esempio esce con codice 2 per design]
`z201-credentials` contiene una credenziale sintetica inserita intenzionalmente per il testing
del credential scanner. **Non** trattare l'exit code 2 di questo esempio come un vero
incidente di sicurezza.
:::

**Parti da qui se:** vuoi vedere come il credential scanner rileva e segnala i segreti.

---

### z405-unused-assets — Integrità degli Asset {#example-z405}

**Directory:** `examples/z405-unused-assets/`
**Engine:** `standalone`
**Z-Code:** Z405 `UNUSED_ASSET`
<ZenzicOutput status="error" exitCode={1} compact />

Contiene `assets/banner.png` — un file immagine che esiste su disco ma non è mai
collegato da nessun documento Markdown. Zenzic rileva l'asset orfano e riporta Z405.

**Parti da qui se:** vuoi verificare che ogni asset del progetto sia effettivamente utilizzato.

---

### z601-brand-obsolescence — Obsolescenza del Brand {#example-z601}

**Directory:** `examples/z601-brand-obsolescence/`
**Engine:** `standalone`
**Z-Code:** Z601 `BRAND_OBSOLESCENCE`
<ZenzicOutput status="error" exitCode={1} compact />

Il `.zenzic.toml` dichiara `OldPlatform` come nome brand obsoleto. Il file `docs/index.md`
del fixture menziona `OldPlatform` — generando finding Z601 per ogni occorrenza.

**Parti da qui se:** mantieni un elenco governance di nomi prodotto o brand deprecati
che devono essere eliminati dalla documentazione.

---

### z602-i18n-parity — Parità i18n {#example-z602}

**Directory:** `examples/z602-i18n-parity/`
**Engine:** `standalone`
**Z-Code:** Z602 `I18N_PARITY`
<ZenzicOutput status="error" exitCode={1} compact />

`docs/en/` contiene due pagine: `index.md` e `guide.md`. Il locale italiano
`docs/it/` ha solo `index.md` — `guide.md` è assente. Zenzic rileva il gap di parità
e riporta Z602.

**Parti da qui se:** mantieni documentazione multilingua e devi verificare che ogni
pagina tradotta in un locale esista anche in tutti gli altri locale configurati.
