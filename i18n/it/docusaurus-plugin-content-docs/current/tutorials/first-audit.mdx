# Il tuo primo audit

**Cosa farai:** passare da una cartella di file Markdown a un report della Sentinella in meno di
tre minuti — senza file di configurazione per iniziare.

:::tip Prerequisiti
Ti serve [uv](https://docs.astral.sh/uv/) nel `PATH`. Il resto è gestito automaticamente.
:::

---

## Step 1 — Esegui Zenzic senza installarlo {#step-1-uvx}

Punta Zenzic su qualsiasi cartella Markdown. Nessun ambiente virtuale, nessun `pip install`:

```bash
uvx zenzic check all --docs percorso/alla/tua/docs
```

`uvx` scarica Zenzic in un ambiente isolato e lo elimina al termine del comando.
Questo è il workflow consigliato per la CI e per provare Zenzic su repository sconosciuti.

---

## Step 2 — L'Assedio e lo Scudo {#step-2-siege}

Prima di configurare qualsiasi cosa, osserva Zenzic proteggere un repo volutamente compromesso:

**L'Assedio** — esegui l'atto 2 (demo credenziale esposta):

```bash
uvx zenzic lab 2
```

Zenzic scansiona il fixture `security_lab` incluso e attiva l'**exit code 2** con
il banner Security Breach — l'allerta non sopprimibile per una credenziale esposta:

```text
╭────────────────────── SECURITY BREACH DETECTED ──────────────────────╮
│                                                                       │
│  ✘ Finding:   Secret detected (aws-access-key) — rotate immediately. │
│  ✘ Location:  docs/how-to/configure.md:4                             │
│  ✘ Credential: AKIA************MPLE                                  │
│                                                                       │
╰───────────────────────────────────────────────────────────────────────╯
```

La credenziale mascherata, l'exit non-zero: è così che Zenzic insegna.

**Lo Scudo (Obsidian Seal)** — ora esegui l'atto 0:

```bash
uvx zenzic lab 0
```

Vedrai l'Obsidian Seal: ogni controllo verde, exit 0. Il contrasto è la lezione —
lo stesso motore che ha rilevato il segreto ha appena confermato che la documentazione
pulita è genuinamente pulita.

**Esplora l'arsenale completo:**

```bash
uvx zenzic lab   # menu interattivo di tutti gli scenari
```

---

## Step 3 — Inizializza il tuo Porto Sicuro {#step-3-init}

Quando sei pronto a integrare Zenzic nel progetto, genera un `zenzic.toml` con un comando:

```bash
cd il-tuo-progetto/
zenzic init
```

Zenzic ispeziona la directory e pre-configura il motore automaticamente:

```text
Created zenzic.toml
  Engine pre-set to docusaurus (detected from docusaurus.config.ts).

Edit the file to enable rules, adjust directories, or set a quality threshold.
Run zenzic check all to validate your documentation.
```

Il file generato è commentato — ogni opzione è disabilitata con una breve spiegazione.
Aprilo, decommentate quello che ti serve, lascia il resto.

:::note Usi pyproject.toml?
```bash
zenzic init --pyproject
```
Questo aggiunge una sezione `[tool.zenzic]` al tuo `pyproject.toml` esistente invece di
creare un file separato.
:::

---

## Step 4 — Esegui il tuo primo audit reale {#step-4-audit}

```bash
zenzic check all
```

La Sentinella scansiona ogni file Markdown, valida i link interni rispetto alla Virtual Site Map,
controlla le ancore, cerca credenziali, esegue le regole personalizzate — poi stampa un report
strutturato ed esce con un codice leggibile dalla macchina:

| Codice | Significato |
| :---: | :--- |
| **0** | Pulito — nessun problema rilevato |
| **1** | Risultati — problemi di qualità della documentazione rilevati |
| **2** | Shield — credenziale esposta rilevata (mai sopprimibile) |
| **3** | Blood Sentinel — tentativo di path traversal rilevato (mai sopprimibile) |

Un'esecuzione pulita si presenta così:

```text
 ✔  No broken links found
 ✔  Shield: no credentials detected
 ✔  Blood Sentinel: no path-traversal attempts
 ✔  No orphaned pages
────────────────────────────────────────
  Files scanned: 42    Elapsed: 0.31 s
```

## Cosa fare dopo? {#next}

- **Strict mode** — aggiungi `--strict` per validare anche gli URL esterni
- **Esporto SARIF** — `zenzic check all --format sarif` per l'integrazione con GitHub Code Scanning
- **Regole personalizzate** — aggiungi voci `[[custom_rules]]` a `zenzic.toml` per applicare i tuoi pattern
- **Codici di findings** — consulta il [riferimento ai Finding Codes](../reference/finding-codes) per il
  catalogo completo `Zxxx`
